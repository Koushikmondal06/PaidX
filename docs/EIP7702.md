# EIP-7702 Account Upgrade Specification & Reference

## 1. Overview
EIP-7702 allows standard Ethereum Externally Owned Accounts (EOAs) to temporarily or permanently designate a smart contract implementation to execute on their behalf, unlocking ERC-4337 and ERC-7715 scoped execution delegation without moving assets to a separate contract address.

## 2. Minimum MetaMask Version Requirements
- **Minimum MetaMask Extension Version**: **v12.10.0** (v12.12.0+ recommended for stable production ERC-7715 permissions)
- **Minimum MetaMask Mobile Version**: **v7.35.0+**
- **Supported Network**: Ethereum Sepolia (`11155111`)

If a user connects with an older MetaMask version, the capability check (`wallet_getCapabilities`) will report that atomic batching / smart account capabilities are unavailable, triggering the manual fallback flow.

---

## 3. Delegation Bytecode Format & Detection
When an account is upgraded to a smart account under EIP-7702:
1. `publicClient.getCode({ address })` returns bytecode with the standard EIP-7702 designation prefix:
   ```
   0xef0100 <20-byte implementation contract address>
   ```
2. PaidX extracts the 20-byte delegate address:
   ```ts
   const delegateAddress = "0x" + code.substring(8, 48);
   ```
3. PaidX dynamically queries `@metamask/smart-accounts-kit` for the current network environment (`getSmartAccountsEnvironment(CHAIN_ID)`).
4. The extracted `delegateAddress` is compared against `env.implementations.EIP7702StatelessDeleGatorImpl`:
   - **Equal**: Account is properly upgraded to the official MetaMask stateless delegator.
   - **Different**: Account has a foreign delegation. PaidX warns the user and never overwrites foreign delegations silently.
   - **Empty or `0x`**: Account is a standard non-upgraded EOA.
   - **RPC Error / Timeout**: Status is marked `unknown` (never guessed or fabricated).

---

## 4. Triggering Upgrade via MetaMask
MetaMask extension accounts cannot call `signAuthorization` directly. In accordance with MetaMask's official developer documentation:
- Upgrades are triggered by sending a batch of two calls via `wallet_sendCalls` (EIP-5792):
  ```json
  [
    { "to": userAddress, "data": "0x", "value": "0x0" },
    { "to": userAddress, "data": "0x", "value": "0x0" }
  ]
  ```
- MetaMask intercepts this batch on Sepolia and displays the smart account upgrade prompt to the user.
- Upon approval, PaidX polls `getUpgradeStatus` with exponential backoff for up to 60 seconds until the on-chain bytecode confirms.

---

## 5. Manual Fallback Steps
If `wallet_sendCalls` is unsupported by the user's browser or wallet:
1. Open the MetaMask browser extension.
2. Click the Account Selector at the top.
3. Open Account Details / Settings.
4. Select **"Enable Smart Account features"** (or switch account to Smart Account mode).
5. Return to PaidX and click **"Check again"**.

---

## 6. Server-Side Verification Guard
Client-sent upgrade flags (`smart_account_upgraded: true`) are **never trusted**.
Whenever a wallet is saved or an ERC-7715 permission is registered, the server executes its own authoritative `getCode` query against `RPC_URL_SERVER` and validates against `@metamask/smart-accounts-kit` before storing `smart_account_upgraded = true`.
